# Squatter — agent notes

iOS lifting-form coach: record a set (squat / bench / deadlift), offline
Vision 3D-pose analysis, per-rep metrics + rule findings + optional LLM
coaching, VBT bar velocity + 1RM estimate. Single dev (Yarik), commits go
straight to `main`.

**Before designing or implementing a feature, read `docs/architecture.md`**
— it holds the dependency graph, pipeline stage table, persistence rules,
measured device facts, feature recipes, and the real-footage replay
workflow. It replaces most code-reading. Keep it (and this file) updated in
the same commit as structural changes.

## Build / test / deploy

The `.xcodeproj` is **generated by XcodeGen** from `project.yml` — run
`xcodegen generate` after adding/removing files, never edit the project
file directly.

```sh
xcodegen generate                                    # after file add/remove
xcodebuild test -project Squatter.xcodeproj -scheme Squatter \
  -destination 'platform=iOS Simulator,name=iPhone 17 Pro' -quiet
xcodebuild -project Squatter.xcodeproj -scheme Squatter \
  -destination generic/platform=iOS -allowProvisioningUpdates -quiet build
xcrun devicectl device install app --device <udid> \
  ~/Library/Developer/Xcode/DerivedData/Squatter-*/Build/Products/Debug-iphoneos/Squatter.app
```

`xcrun devicectl list devices` for the udid (16 Pro Max "tts0" = LiDAR test
device). Swift 6, strict concurrency, iOS 17 target (some UI
`@available(iOS 18)`), Swift Testing. Simulator "Busy / failed preflight
checks" → `xcrun simctl shutdown all` and retry.

## Architecture (one line each; full map in docs/architecture.md)

- `Squatter/Capture/` — `CameraService` (video + LiDAR `DepthSidecar`),
  `FramingChecker`, live rep counter/voice coach hooks.
- `Squatter/Analysis/` — pure, UI-free, compiles standalone on macOS:
  `PoseExtractor` → `JointTrackRepair` (despike + ≤2-frame gap bridge on
  the raw series, *after* `TrackingQuality` measures it; touched joints
  flagged, and flagged joints may never assert a fault) →
  `JointSeriesSmoother` → body-geometry scan + `SkeletonCorrector`
  (squat+LiDAR: re-poses the pelvis to the 2D image evidence, deepen-only,
  only at depth) → `RepSegmenter` → `MetricsCalculator`
  (+`VelocityCalculator`, which despikes its `barTrack` copy at
  consumption) → `FormRules`, gated globally and per-rep by
  `TrackingQuality`. **All thresholds live in `AnalysisTuning.swift`.**
  `PlateDetector` (review-time plate classes by diameter+color),
  `FormFaultDetector` (per-frame fault flags coloring the video overlay),
  and `LiveRepCounter` (2D live rep counting) also live here.
- `Squatter/Coach/` — Anthropic API coaching: `CoachClient` +
  `KeyframeExtractor` (rep-bottom JPEGs); `CoachPrompt` embeds live
  thresholds; `CoachReport` mirrors `CoachPrompt.outputSchema` — keep in
  sync. Report cached as `.coach` beside the video; API key in the Keychain
  (`CoachKeyStore`).
- `Squatter/UI/` — SwiftUI, Mazda-Kodo visual language (`Theme.swift`).
  `HomeView` owns all routes; review screen has weight field + plate
  calculator; `BodyScanView` = profile page + three-pose scan flow.
- `Squatter/Models/` — `WorkoutSession` (SwiftData, stores full analysis
  JSON), `BodyGeometryProfile` + `PlateCatalog` (user-taught plates:
  diameter-first, color tie-break) as JSON in Application Support.

## Domain facts that bite

- **Never hand sidecar depth to Vision** — `VNDetectHumanBodyPose3DRequest`
  hard-aborts (uncatchable C++ assert) on depth without camera calibration.
  Depth is only sampled directly off the maps.
- Vision's 3D model space is **root-anchored and not world-aligned** for a
  lying body: rep signals must be joint-to-joint *distances*, never axis
  projections.
- Vision's 3D **proportions are priors, not measurements**: bodyHeight
  ≈ 1.80 m, shoulder width ≈ 0.34 m, hip width ≈ 0.31 m for everyone. Judge
  body proportions from 2D image spans / metric image measurements, never
  model space.
- Vision poses deep-squat bottoms **too shallow while keeping bone lengths
  consistent (~0.02%)** — only the 2D image points reveal true depth. Trust
  the deeper of model vs image.
- Standing bones hang vertical: image-y drop × `metersPerImageHeight` = true
  length, yaw- and aspect-free. Horizontal metric spans need
  `JointSeries.imageAspectRatio`.
- Image-space points come from the 2D pose request; the 3D observation's
  `pointInImage` drifts ~50 px.
- `TrackingQuality.boneLengthJitter` gates form rules (> 0.01); it is
  computed **before** skeleton correction and track repair — both would
  mask the flicker it measures. Clean squats: 0.0002–0.003. The per-rep
  timeline gate (same 0.01) suppresses single flickering reps; dropouts
  read as *clean* jitter, so it catches flicker, not occlusion.
- Analysis JSON is persisted: new fields on `SquatAnalysis`/`RepMetrics`/
  `Finding`/`JointSeries`/`JointFrame` must be optional (old sessions
  decode).
- Plate counts are unknowable from one view (plates stack) — `PlateDetector`
  reports classes; the user sets counts.

## Debugging with real recordings

See "Real-footage replay workflow" in `docs/architecture.md` for the full
pull → sqlite-extract → standalone-swiftc replay loop, including the exact
file list and the JSON dictionary-encoding gotcha. Device-extracted series
are ground truth; macOS Vision ≠ iOS Vision. `devicectl device copy to`
seeds profile/catalog JSON into the app container.

## Form standards

Squat is judged against Chinese weightlifting (high-bar) practice: full
depth, near-vertical torso, knees over toes, controlled ~1–2 s descent —
personalized by the body scan's unloaded deep hold when a profile exists
(never demanding more than the lifter's measured mobility). Bench:
lower-chest touch, elbows 45–70° from torso, vertical forearms, J-curve bar
path, full lockout. Deadlift: neutral spine, bar on the legs, hips and
shoulders rising together, tall lockout (thresholds still synthetic-only).
Cite these when writing findings/prompt text.
