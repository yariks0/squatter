# Squatter — agent notes

iOS lifting-form coach: record a set (squat or bench press), offline Vision
3D-pose analysis, per-rep metrics + rule findings + optional LLM coaching.
Single dev (Yarik), commits go straight to `main`.

## Build / test / deploy

The `.xcodeproj` is **generated by XcodeGen** from `project.yml` and may be
regenerated at any time — run `xcodegen generate` after adding/removing files,
and never edit the project file directly.

```sh
xcodegen generate                                    # after file add/remove
xcodebuild test -project Squatter.xcodeproj -scheme Squatter \
  -destination 'platform=iOS Simulator,name=iPhone 17 Pro' -quiet
xcodebuild -project Squatter.xcodeproj -scheme Squatter \
  -destination generic/platform=iOS -allowProvisioningUpdates -quiet build
xcrun devicectl device install app --device <udid> \
  ~/Library/Developer/Xcode/DerivedData/Squatter-*/Build/Products/Debug-iphoneos/Squatter.app
```

`xcrun devicectl list devices` for the udid. Swift 6, strict concurrency,
iOS 17 target (some UI is `@available(iOS 18)`), tests use Swift Testing.

## Architecture (one line each)

- `Squatter/Capture/` — `CameraService` (AVCapture video + LiDAR depth
  sidecar via `DepthSidecar`), `FramingChecker` live full-body check.
- `Squatter/Analysis/` — the pipeline: `PoseExtractor` (video → `JointSeries`;
  resumes if the decoder dies mid-file) → `JointSeriesSmoother` →
  `SkeletonCorrector` (squat + LiDAR only: 2D image points × metric scale ÷
  scanned metric femur give the femur's true elevation; the pelvis is
  re-posed to it, deepen-only, and only when the model is already deep) →
  `RepSegmenter` → `MetricsCalculator` → `FormRules` findings, gated by
  `TrackingQuality`. **All thresholds live in `AnalysisTuning.swift`.**
- Body geometry: `BodyGeometry` (model-space bone lengths) and
  `MetricBodyGeometry` (real meters, from standing-frame image drops ×
  LiDAR scale) are scanned from each session's standing frames; a
  `BodyGeometryProfile` from the dedicated body-scan flow (`BodyScanView`,
  stored as JSON in Application Support) overrides the in-session estimate.
- `Squatter/Coach/` — Anthropic API coaching: `CoachPrompt` (system prompt
  embeds live thresholds; user turn packs metrics + keyframes), `CoachClient`,
  `CoachReport` (mirrors `CoachPrompt.outputSchema` — keep in sync).
- `Squatter/UI/` — SwiftUI; report = `ReportView` (skeleton overlay,
  `RepTimelineView` scrub chart, findings, coach section). Visual language is
  Mazda-Kodo-inspired (`Theme.swift`: `Kodo` palette, Soul Red accent).
- `Squatter/Models/` — `WorkoutSession` (SwiftData; stores the full analysis
  JSON, so decoded types need backward-compatible optional fields).

## Domain facts that bite

- **Never hand sidecar depth to Vision** — `VNDetectHumanBodyPose3DRequest`
  hard-aborts (uncatchable C++ assert) on depth without camera calibration.
  Depth is only sampled directly for metric height in `PoseExtractor`.
- Vision's 3D model space is **root-anchored and not world-aligned** for a
  lying body: rep signals must be joint-to-joint *distances* (bench =
  wrist–shoulder distance), never axis projections.
- Image-space points come from the 2D pose request; the 3D observation's
  `pointInImage` re-projects through an assumed camera and drifts ~50 px.
- Vision RGB `bodyHeight` is a ~1.80 m prior, not a measurement.
- Vision's 3D pose at deep-squat bottoms is **internally consistent but
  posed too shallow** (pelvis high, bone lengths hold to ~0.02%): length
  constraints can't see the error; only the 2D image points (which follow
  real pixels) reveal it. Trust the *deeper* of model vs image — the model
  never exaggerates depth, the image goes shallow under camera pitch or 2D
  glitches.
- `TrackingQuality.boneLengthJitter` gates form rules (> 0.01 → single
  "tracking unstable" finding). Don't tune segmentation on jittery footage —
  clean squat sessions sit at 0.0003–0.003.
- Analysis JSON is persisted: new fields on `Finding`/`RepMetrics`/
  `SquatAnalysis` must be optional (old sessions still decode).

## Debugging with real recordings

- Pull app data off the phone:
  `xcrun devicectl device copy from --device <udid> --domain-type
  appDataContainer --domain-identifier com.yarik.squatter --source
  "Library/Application Support/Recordings" --destination <dir>` (same for
  `default.store*`; extract analysis JSON from `ZWORKOUTSESSION.ZANALYSISDATA`
  with sqlite3 `writefile`).
- The whole Analysis layer compiles standalone on macOS: `swiftc` a small
  `main.swift` against `Analysis/*.swift + Models/ActivityType.swift +
  Capture/DepthSidecar.swift` to replay extraction/segmentation on pulled
  videos without the phone. macOS Vision ≠ iOS Vision (different noise), so
  device-extracted series are the ground truth for tuning.

## Form standards

Squat is judged against Chinese weightlifting (high-bar) practice: full depth,
near-vertical torso, knees over toes, controlled ~1–2 s descent. Bench:
lower-chest touch, elbows 45–70° from torso, vertical forearms, J-curve bar
path, full lockout. Cite these when writing findings/prompt text.
